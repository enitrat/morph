# Morph maintenance redesign

## Scope and evidence

The objective covers all first-party code, including the development bridge, overlay, recorded playground, example animation engine, and build adapters. This is an open inventory, not a claim that the repository is finished. Three read-only passes inspected production modules and relevant tests. Recorded variants and smaller example utilities received searches and sampling; exhaustive review of those files remains open.

Baseline at `39079a9`: 290 package tests in 49 files and 25 playground tests in two files passed. The earlier handoff's test counts are stale. Commands are `pnpm test`, `pnpm --filter morph-site test`, `pnpm typecheck`, and `pnpm check:prod`. Browser verification must cover actual rendered behavior for UI changes.

## Architecture

Morph lets a designer select running React code, ask for alternatives, compare them, refine, and keep one. The bridge plans work, runs detached agents in isolated git worktrees, and uses a journal to safely apply variants to the working tree. The overlay discovers source locations and presents the bridge's page view. The playground implements the same protocol using recorded scenes and a virtual repository.

The desired ownership is a durable checkout checkpoint that atomically publishes session rounds and working-tree intent, owned attempts for detached execution, and a browser client that receives ordered authoritative observations. Session policy and working-tree policy remain separate functions within that commit boundary. Presentation metadata belongs to the browser. Recorded playback owns only the data needed to replay the same contract. Required recovery for crashes, hand edits, and external framework quirks stays at those boundaries.

## Design decisions

### S1. Current kept repository

The current product offers keep and reset, with no history checkout. Candidate A stores only the current repository; provenance is already on each immutable revision. Candidate B retains an append-only keep-event stream and derives current code. A removes a redundant representation and its traversal without losing a current feature. B retains unused history infrastructure, so A was selected.

Changed contracts remove `Version`, `Snapshot.versions`, and `Snapshot.at`. All repository callers migrate together. The ledger still lists one row per changed file, labeled with its latest variant, with a diff against the original. Keep preserves other files; refinement builds on the kept revision; reset restores original code and empties sessions/log.

### B1/O1/O2. Durable sessions and ordered client observations

The accepted target retains detached processes and publishes round transitions and working-tree write intent in one atomic checkpoint. Immutable SessionId remains the round/command identity; a separate ThreadId will identify the browser pin. A long-lived supervisor would introduce extra process lifecycle machinery. Separate round and journal files would require another receipt protocol to distinguish an interrupted refinement keep. [The detailed contract](session-design.md) records states, execution ownership, migration, and required crash evidence; checkpoint closure, detached planning, owned attempts, and stable browser threads are implemented.

The implemented first unit captures sessions/jobs once, settles the tree, projects the page, and allocates a persisted observation number under one live-tree lock. The overlay accepts only newer pages. Successful ask/refine replies acknowledge their command independently: a late reply reconciles against the already accepted newer page. Independent review identified this second requirement after the initial freshness guard; without it, an already closed session could leave a pending pin indefinitely. Playground observations remain monotonic across reset.

Session lifecycle publication now shares the live lock and checkpoint with file intent. Variant and planner publication share the checkpoint lock. Stable thread identity and explicit submissions have replaced pending pin flags and refine rollback.

### S6. Playback transport

An explicit paused/playing clock preserves the existing hook API and silent playback when Web Audio is unavailable. An audio-owned clock would change behavior because the synthesized sound deliberately does not seek with the displayed track, so that alternative was rejected.

The first implementation rebased position each animation frame. Twelve browser assertions passed, but independent review found accumulated floating-point error at 60 Hz: one second became just less than one, and the track did not stop at exactly 204 seconds. The expanded browser script reproduced that failure. That design was rejected.

The accepted model keeps a fixed playing origin and start time, plus the latest sampled time. Only the sampled time moves on an animation frame. Paused state holds a position and no timestamps. Explicit events replace `Partial` updates; one shell starts/stops sound and animation scheduling when the transport tag changes. The position hook derives a stable value from the fixed origin and latest sample. Preferences and the stable control snapshot remain separate from the clock. The shared store still survives component replacement.

## Required boundary behavior to retain

- Compare-before-write crash recovery protects user edits after interrupted multi-file writes.
- Three-way merge, pinned conflicts, and session priorities implement concurrent variant placement.
- Unique lock contenders and dead-owner cleanup coordinate separate processes.
- Workspace-relative dependency links preserve isolated execution.
- Bundler frame normalization, cross-origin stylesheet handling, and React development-fiber interop belong in adapters.
- Theme inheritance pinning, preview restoration, font registration, and shadow-root CSS rewriting encode actual external constraints.
- Recorded variant files are deliberate product fixtures.
- CLI recovery commands work when a broken edited app cannot render the overlay.

## Stable threads and unresolved submissions

A thread derives its identity from its oldest immutable parent round. Page views expose that identity plus current words and targets; browser pins/cards use ThreadId while variant commands and suggestions use the current SessionId. Measurements carry their round ID and stale measurements are ignored. A new observed round clears its predecessor's refinement draft. Checkpoint import and the wire schema reject multiple open rounds for one derived thread rather than silently collapsing their pins.

Locating, sending, and uncertain are explicit local submission states. A tab-owned sessionStorage entry records the exact parsed Ask/Refine before POST. Reload restores it as uncertain. Retry uses the same immutable request, including after server closure; playground keep/discard/reset now retain terminal IDs too. Absence alone never proves rejection. New page evidence or command acknowledgement clears only the matching submission. Per-thread storage plus matching request IDs prevents old replies from deleting a later request.

Independent review rejected three ownership gaps in initial implementations: canceled lookups could still write/send, cancellation left the next refine blocked, and unmounted controllers retained lookup authority. One overlay action owner now handles initial ask and refinement, revokes matching operations on successful cancellation or observed successors, checks ownership after lookup, and clears outstanding lookup ownership on unmount. Already-sent commands retain recovery data. This removes optimistic ID replacement/rollback without adding a second persisted server identity registry.

The separate originalBefore poll-count measurement in live.ts still lacks proof that HMR restored the original DOM. Round tagging prevents cross-round writes but does not solve this provenance defect. It remains an explicit next redesign item, together with the untouched inventory.
